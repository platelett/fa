# 优化历程

这个仓库里的自定义实现来自两种写法：TileLang 用较高层的语言组织计算；CCE 直接安排底层计算、搬运和同步。TileLang 保留原流式路线，并新增把输出累加留在片上的实现；CCE 分为主要使用 FP16 和 FP32 做中间计算的两个版本。Torch 调用现成算子，作为比较对象，没有独立的手写优化历程。

这里按“为什么改、改了什么、结果怎样”整理历史。想直接看一条路线，可以从下面进入：

| 路线 | 这条历程主要讲什么 |
|---|---|
| [TileLang](tilelang.md) | 尝试更大的分块、查清计算与搬运的关系，最后选择三个流水槽；迁移到新的归约接口后重新验证 |
| [TileLang FP32](tilelang-fp32.md) | 把输出累加留在片上，用本来就需要的计算填补等待，再检查局部优化是否真的让整体变快 |
| [CCE FP16](cce-fp16.md) | 从两次矩阵乘法开始，把搬运和计算接起来，再加入完整 attention；最大的后期收益来自把输出累加留在片上 |
| [CCE FP32](cce-fp32.md) | 提高中间计算精度后重新安排片上空间，用独立搬运队列和有用的计算填补等待 |
| [历史尝试索引](attempts.md) | 查找没有进入最终实现的尝试，以及暂停、失败或仍无结论的分支 |

## 先知道 attention 在做什么

可以把它看成三道工序：

1. **算分数**：让 query（Q）和 key（K）做矩阵乘法，得到相关程度。
2. **算权重**：对分数做 softmax，得到每个 value 应占的权重。
3. **算输出**：让权重和 value（V）做矩阵乘法，再把各块的贡献合起来。

序列很长时，完整分数矩阵太大，不能全部存下来。实现会把它切成许多块，处理一块就更新统计量和输出。这就是这里说的“在线 softmax”。它保存目前的最大值、权重总和以及输出累加值，而不是保存整个分数矩阵。

昇腾把两类工作交给不同的计算单元：**Cube 做矩阵乘法，Vector 做 softmax 和输出累加**。还有专门的搬运单元。优化希望它们同时推进，而不是做完一道工序才开始下一道。

```text
Cube   : score 0 | score 1 | score 2 | partial output 0 | ...
Vector :         | softmax 0 | softmax 1 | merge output 0 | ...
DMA    :         load next / store previous, when their slots are free
```

这只是帮助理解的示意。真正的顺序受数据是否就绪、缓冲区能否覆盖等条件限制。

## 选定实现的成绩

下面新增 TileLang FP32 的实测结果，其他列保留历史成绩。各列不是同一轮测量，流式 TileLang 的旧成绩也不代表当前本地源码更新后的结果。输入和输出都是 FP16；FP32 指中间计算精度，Cube 与 Vector 之间传递的数据仍是 FP16。

| Batch / Length | TileLang 流式（历史），ms | TileLang FP32，ms | CCE FP16，ms | CCE FP32，ms |
|---|---:|---:|---:|---:|
| 2 / 131072 | 1118.169 | 954.812 | 572.472 | 714.630 |
| 2 / 65536 | 276.640 | 233.315 | 143.603 | 180.099 |
| 1 / 32768 | 34.508 | 29.161 | 18.440 | 23.018 |

最大输入上，CCE FP16 达到约 **97.3%** 的本机 25 Cube 名义峰值，CCE FP32 约 **78.0%**，新 TileLang FP32 约 **58.4%**。所有列统一用 25 个 Cube 的峰值作参照，TileLang 实际使用 24 组。这个比例用两次矩阵乘法的计算量除以完整 attention 的用时，不表示某个单元忙了多少时间。

各列测试的环境、采样方式和运行命令见[仓库 README](../../README.md)。各篇中的历史表格来自相应阶段的对照实验，不能把不同阶段的百分比直接相乘，拼成一条累计加速曲线。早期 CCE 还没有输出合并和归一化，文中会明确指出。

## 这份整理覆盖到哪里

TileLang 的早期记录不完整，本文整理能确认的分块、消融和流水深度实验，以及 PR #1852 下的迁移与复测。新篇目继续介绍独立 FP32 实现的空间安排、依赖调度和布局取舍。CCE 覆盖从 QK/PV 实验、底层流水研究，到完整 attention、片上输出累加，以及 FP32 空间重设计、读写布局和归约调度的主要阶段。

为了方便阅读，正文按设计问题合并多轮实验，没有逐个复述历史目录。索引保留各类尝试的去向。原始日志、二进制和研究分支不放进公开仓库；这里公开的是历程整理、选定实现和明确标注的对照。
