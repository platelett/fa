# 历史尝试索引

正文只讲主要转折。这一页补上其他尝试的去向，尤其是没有采用的改动。表中的“保留”指进入相应阶段的后续设计，不表示那个旧版本现在仍在公开仓库中。

这些是原有研究记录的中文整理，原始实验报告、运行日志和旧实现保留在研究档案中。本仓库不发布 `results/`；下方的档案编号或目录名用于定位原记录，不是公开下载链接。没有找到最终实机证据的分支，明确列为无结论。

## TileLang

| 尝试 | 想解决什么 | 结果与去向 |
|---|---|---|
| 增大 key 块、增加 query 行数 | 少做循环，降低每块开销 | key 块变宽慢约 5%–8%；增加行数大体持平；更大组合受容量和接口限制，没有选入 |
| 去掉 Cube、Vector、搬运或输出更新 | 查清单独工作与并行工作各要多久 | 纠正只凭“去掉一项快多少”判断成本的做法；这些版本只用于诊断 |
| 两个、三个、四个工作区槽 | 增加双方周转余地 | 历史测试选择三个；四个没有进一步明确收益 |
| FP16 融合 softmax、融合转换与缩放 | 减少 Vector 计算与转换 | 当时接口不支持所需组合，没有成为可运行优化 |
| 修复分块乘法的初始化条件 | 确保只在第一个累加块清零 | TIR 条件不能用会被 Python 提前求值的逻辑表达式；修复后继续实验 |
| PR #1852 下的普通 max/sum softmax | 去掉额外融合接口依赖，使用重构后的归约 | 已进入公开实现；重新比较相同环形结构的两个、三个槽，三个在三规模均更快 |

档案入口：`shape_ablation_opt_report.md`、`gm_bandwidth_contention_report.md`，以及公开前的 `pr1852/experiment.md`。前两份报告的一些早期成本分解过强，正文只保留独立/并行对照能支持的观察。

### 新 TileLang FP32 路线

这些尝试属于独立的片上输出累加版本，完整过程见 [TileLang FP32](tilelang-fp32.md)。

| 尝试 | 想解决什么 | 结果与去向 |
|---|---|---|
| 把必要的分数缩放放到最大值计算之后 | 用有效计算覆盖统计量和广播的等待 | 单独约快 2.6%，进入最终版 |
| 删除减法与指数之间的外部填充 | 避免重复计算遍历本身已提供的依赖间隔 | 单独约快 3.5%，进入最终版；不是通用最短延迟结论 |
| 把同一广播系数放在两个不同位置 | 减少两路读源的存储竞争 | 组合后仍有小幅收益，保留；没有消除所有冲突 |
| 转换与缩放跨区域往返 | 改善原地读写 | 完整用时中性，未采用 |
| UB 行距从 512 扩为 520 个 FP32 元素 | 将归约首层从 64 条短指令变成 8 条长指令 | 前后转换和打包变得更碎，整体中性，未采用 |
| 合并连续 K 搬运 | 减少搬运描述符和地址计算 | 指令减少但完整用时中性，未采用 |
| Vector 只搬运并发信号 | 判断主要计算暴露了多少成本 | 仅作诊断，不是可运行的正确 attention 实现 |

上述单项百分比来自各自匹配对照，不能直接相加。最终组合在三个完整 case 上
减少约 6.4%-6.8% 用时，与优化前输出逐位相同。
档案入口：`tl_attention_fp32_v1_20261008`、`tl_attention_fp32_structure_20261008`。

## CCE：从 QK/PV 到完整 FP16 attention

### 早期 QK/PV：档案 01–19

这一阶段没有输出合并和最终归一化。`QK/PV` 指分数矩阵乘法和权重×value 矩阵乘法。

| 档案 | 尝试及原始问题 | 结果与去向 |
|---|---|---|
| 01 | 首个真实 QK、max/exp、PV 路径 | 冻结作参考；最初计时遇到设备占用，不能用于排名 |
| 02 | 四种布局与顺序组合 | 数值检查通过；转置密集布局严重慢。之后两条旧顺序因与修正后的设计不符而暂停，不能视为最终模式 |
| 03 | 转置 max 的相位错开、adjacent/prefix 树及累加区 | 目的都是避免对应源访问同相位；形成早期可用归约，后来被新树替代。探针通过不等于完整算子通过 |
| 04 | 转置 S/P 改成打包的原生 NZ | 消除窄条搬运，保留；成为转置后续路线基础 |
| 05 | QKV 重放与 Vector 绕过 | 用于诊断合在一起为何慢，没有把无计算版本作为优化产物 |
| 06 | 按消费者顺序发出输入准备 | 某些规模获益，进入早期 v2；当时尚未满足后来修正的完整 Q 驻留顺序 |
| 07 | 用另一种物理 L0C 空闲信号替代宽泛等待 | 完成对照的候选普通方向更慢、转置持平，未采用；其余同类目录有构建失败或未运行，不能混作性能结论 |
| 08 | PV 分 query 半块、使用 UnitFlag、去掉多余 FIX 等待 | 有用部分合入早期 v3；单独改变 UnitFlag 流的效果不统一 |
| 09 | 独立 direction 与 PV-half 探针 | 有局部检查；部分计时主动停止，作为暂停分支保存 |
| 10 | 将选中的早期改动合成 v3 | 通过该阶段完整门槛，随后被分半输入、Q512、分片 V 路线替代 |
| 11 | 更早归还 A 半区 | 片上搬运忙碌时间略降，整算子却更慢，未采用 |
| 12 | 重放 A/B 操作数 | B 侧重放影响更明显，推动输入供给研究；重放版仅是诊断 |
| 13–14 | 更早归还 B、维持 direction 状态 | 找不到最终设备比较，保留为无结论分支 |
| 15 | 两次小 MAD 配一次宽 FIX，L0B 分半 | 普通方向收益更清楚，成为后续基线的一部分 |
| 16 | Vector 不搬运、不计算，只发信号 | 用于判断暴露的 Vector 成本；与提前归还槽同时变化，不能单独算作带宽收益 |
| 17 | 修正 Q512 驻留与整批 Q/key 的外层顺序 | 保留到后续基线；并非单独证明所有搬运都已被隐藏 |
| 18 | V 按 128 面板消费顺序加载 | 整套新基线三规模胜过 v3，保留；其中孤立 V 改动的净收益较小 |
| 19 | Q256/512/768/1024、通信 Q128/256、K512/1024 扫描 | 只测容量可行点。早期 K1024 想改善输出回传合并，但实验尚无该阶段；不能用结果判定这个预期。此轮检查与规模覆盖也有限 |

### 独立底层实验：档案 20–27

这些实验解释“怎样导出结果”，不直接作为完整 FA 成绩。

| 档案 | 尝试及原始问题 | 结果与去向 |
|---|---|---|
| 20 | 两种乘法结果方向配连续/原生布局 | 找到有条件的方向差异；早期坐标解释后来更正 |
| 21 | 经两个 L1 槽中转，凑宽后写出 | 原生 NZ 中转没有稳定收益；目标普通矩阵转换未按预期得到 ND，未采用 |
| 22 | 多种跨行写出的完整地址几何 | 不能只凭 128 宽断言带宽必然减半；需要连同行步长、地址和协议一起看 |
| 23 | 查清 L0C→L1 “数值错”究竟错在哪里 | 数据全部存在，只是保留 NZ 排列，没有变成期望的 ND；不是随机数值损坏 |
| 24–25 | 128×128 跨行写出，UnitFlag 开关与方向；短队列时间线 | 长流水接近不代表启动相同。更正结果方向的坐标含义，保留有条件的实测差异 |
| 26 | 128×256 跨行写出的四组合 | 对齐条件下 M-dir + UnitFlag 接近纯乘法；其他地址/方向不能照搬 |
| 27 | 两次 128×128 MAD 配一次 128×256 FIX | 验证数据正确、稳态接近宽乘法；实际 FA 输入重装收益另由档案 15 检验 |

### 共用源码、顺序与所有权：档案 28–40

| 档案 | 尝试及原始问题 | 结果与去向 |
|---|---|---|
| 28 | 普通三种、转置两种面板复用 | 形成五模式，共用普通/转置代码；转置 Q-K-Q 暂停。QK/PV direction 组合及 Q 驻留长度继续枚举 |
| 29 | 普通方向也直接使用 NZ 做 softmax | 扩成 3+3+2；普通 NZ 在匹配对照中获益，保留 |
| 30 | 很多逻辑 block，缓解结束长尾 | 测到细粒度调度区间，用户选择最大可用逻辑数量；仍是一次 launch |
| 31 | 跨驻留-Q 任务继续 S/P 流水 | 独立研究边界排空；不是无条件获益，也没有用它覆盖旧基线 |
| 32 | 严格消费顺序与显式提前准备对照 | 两种写法没有统一赢家，保持独立；继续拆分变化来源 |
| 33 | 固定二进制、物理配对与地址，拆开加载顺序差异 | 更早发 K 在两代表模式更快；随后发现同时改变 K 的空闲信号，不能全归因于排序 |
| 34 | 联合建模两层加载顺序与 buffer 生命周期 | 同时需要的两个输入不是唯一全序；先统一所有权，再比较顺序。模型不冒充硬件全局最优解 |
| 35 | 最大逻辑数量下重排 P/V/K、提早归还 K | 多个纯顺序尝试持平或更慢；最后读者后归还 K 是有用候选 |
| 36–37 | V 追加许可与每面板独立锁；全面整理搬运/锁粒度 | 从补充许可转向独立 V-panel 所有权，按用户选择保留较清楚的结构；这是一条设计约束 |
| 38 | 只用格雷码更换物理半区编号 | 变慢且没有减少输入加载，拒绝；它未实现用户要的操作数复用 |
| 39 | 真正保留操作数的蛇形遍历 | 确实少搬 Q，需处理 QK/PV 边界半区冲突；整算子没有稳定净收益，保留实验 |
| 40 | 将实际复用作为可选开关 | 便于继续研究；公开 FP32 最终接口未保留 Gray 开关，不能凭旧开关推断默认启用 |

### 加入完整输出：档案 41–42 与后续报告

| 档案入口 | 尝试及原始问题 | 结果与去向 |
|---|---|---|
| 41 / `cce_attention_v1` | 输出贡献返回 Vector，加入系数、分母更新、O 合并和归一化 | 完整 attention 跑通，但比无合并路径慢，进入结构排查 |
| 42 / `packet_ring_v2` | O_partial 按完整通信块配置多代槽 | 去掉额外内部限流，大通信块 K-first 获益明显；小块配置大体持平 |
| `alpha_v3` | softmax 后按块准备 alpha，保存紧凑多代系数 | 减少重复转换与广播，进入后续；不是主要性能突破 |
| `reduce_v4` | 两块归约区交替、错相配对，插入独立工作 | 三布局 max/sum 重写并通过同步对照，用户采用；不复用 S/P 与 O 的活跃空间 |
| `ub_v5` / `gm_lock` | 更大的 O 搬运块与明确 GM 使用区间 | 16 KiB 路径正确后可用，但未稳定胜过旧插入式调度；发现并修复尾部 GM 跨代依赖缺口 |
| `vector_schedule` | 输出与 softmax 的分片/阶段顺序比较 | 一些穿插方式有效，用户更希望结构清楚；后续继续从搬运成本本身找解法 |
| `resident_o` | 缩小 Q 批次，使 O 留在 UB | 去掉运行 O 往返；匹配 Q512 对照快 6.55%，相对当时完整基线三规模快约 8%–9% |
| `resident_family` / `resident_period` | 将片上 O 扩到八模式，调整槽深度与归还者 | 最后读者归还作为所有权修正保留；Q768 四槽优于三槽；批量 O 更新和小标量改动无统一收益 |
| `resident_direction` | 完整输出加入后重新测 QK/PV direction | 两个普通 NZ 模式获益；形成 v13 共用代码，公开选 Q768 的普通 NZ Q-K-Q |
| `o_exposure` / `eight_vs_qkpv` / `terminal_wait` | 判断剩余差距是否来自 O 算术、任务重启或终态等待 | 单项观察不能解释整个差距，未得到可统一采用的新结构 |
| `native_o` / `native_o_split` / `native_o_order` | O 使用 query 连续的原生 NZ，拆 FIX、重排入口 | 布局方法正确，个别 NZ 均值更好，但后续对照不支持统一替换；普通行式会退化 |
| `l1_consumer_layout` / `sp_pitch` / `logical_o` | 改输入打包、S/P 间距或输出存放位置 | 未得到稳定家族收益；某方案大幅增加 workspace，未采用 |
| `p_read_join` | P 的独立只读消费者并行，下一写者前汇合 | 普通 NZ Q-first 有小幅可复现收益，最快 Q-K-Q 没有同样收益；保留局部选项，未叠入公开赢家 |

在约 97% 名义峰值附近，后期试验没有找到能继续稳定改善最快配置、又保持清楚结构的共同方法，因此结束本轮调优。这个停止决定不等于证明已经全局最优。

## CCE FP32

| 档案入口 | 尝试及原始问题 | 结果与去向 |
|---|---|---|
| `vector_fp32_v1` | 保留 FP16 通信，扩大 Vector 主要计算与 O 精度 | 完整八模式可运行；Q512 的 O 占 128 KiB，空间挤压了流水，性能目标未实现 |
| v1 的长遍历间隔、系数布局、sum 中插入转换 | 减少依赖等待与重复展开 | 部分有小收益；普通方向复制系数没有净收益，转置系数安排有效；并非通用银行冲突结论 |
| `fp32_queue_design` / `vector_fp32_v2` | Q256、独立输入输出双队列、完整计算块、独立归约区 | 实测最快配置较 v1 快约 20%；形成 189 KiB 空间规划 |
| v2 的 Q 复用选择 | 减少重复片上输入加载而不新增繁复开关 | 测得搬运减少，但用时大体中性；按几何固定策略，最终接口删除 Gray 参数 |
| `vector_fp32_v3`：统一长空间隔 | 完全去掉 BAR.V，同时保证数据就绪 | 正确但慢 11%–13%，拒绝 |
| v3：统一短空间隔、转置末层加长 | 缩短空等 | 出现数值错误，不能进入性能排名 |
| v3：分层调度、转换/缩放填间隔、按最后读者归还 | 用具体依赖替代全流水等待 | 普通方向约快 9%；转置约慢 6.5%。后续继续优化普通 NZ |
| v4：转换与缩放穿插 max，再复用归约区计算减法和指数 | 先区分 Vector 内部低效与搬运跟不上，再减少空等和读写冲突 | 三个 case 均快约 8%，采用；构成当前版本的基础 |
| v5：分四段转换 P | 用同一批必需转换填补 sum 的多个层间等待 | 三个 case 再快约 2%，采用为当前公开版本 |
| 更均匀地拆分转换与缩放 | 看进一步分段能否改善调度 | 与 v4 基本持平，未采用 |
| K1024 | 增大 key 块，尝试减少跨块工作 | 修复 sum 过早读取后正确，中等输入仍慢约 23%，未采用 |
| O 放外部内存，Q256/512/768；再增大 O 搬运块 | 释放片上空间，允许更大的 Q 和工作区 | 放大搬运块有所改善，但中等输入的最好候选仍比 v4 慢约 7%，未采用 |
| Q128 单/双计算区 | 腾出空间，让更多独立计算交错执行 | 双计算区只略好于同尺寸单区，中等输入两者都比 Q256 v4 慢约 5%，未采用 |

FP32 的正确性测试还覆盖了运行累加值超过 FP16 有限范围、而每块通信值和最终结果仍有限的输入。它验证 FP32 累加的用途，不代表整个实现支持任意范围的输入。

## 怎么定位当前实现

所有当前代码入口见[仓库 README](../../README.md#implementations)。中文历程是这个公开仓库的阅读入口；上面的旧编号只服务于回顾，不是要求运行者准备几十个历史 backend。

整理时没有重新运行旧实验。无法恢复的 TileLang 早期变体、只找到源码没有最终运行的 CCE 分支，以及早期参数扫描不完整的验证范围，都保留为明确缺口，没有补成“测试通过”。
